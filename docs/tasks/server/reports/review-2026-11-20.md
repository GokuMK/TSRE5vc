# Review of feature/server before its merge (2026-11-19/20)

The user asked for an independent review before `feature/server` is
merged. Three reviewers, each new to the code, read what a merge would
bring into main (`main...8338ef73`, about 12,000 lines):

- tasks 01 and 02: the server, the protocol;
- task 05: the simulation on the server;
- task 03 and editor task 10: the route's files, the route switch.

Each finding was checked against the code before it was fixed. Each fix
has a suite check that fails with the fix switched off, except where said.

The user's decisions during the review:
- **The merge comes after task 06 (players)**, the feature's minimum;
  task 07 is not needed for it.
- **The users file is `users.json` in the profile's folder** (a profile
  names one server session: its game root, route, settings and users,
  moved as one folder, never shipped with content). Plain passwords: the
  admin hands them out. `--users <file>` still overrides. The route
  folder's `users.txt` is no longer read; nobody used the broken mode.

## After the review (2026-11-20)

- **Paths saved with 6 digits again** (the user): task 05 had made the
  path writer use 9 significant digits for the run's data, and with it
  every saved path. Six is the most a decimal keeps through a float and
  back, so loading and saving again never changes the file; with nine,
  values recomputed between saves changed their last digits. Now only a
  run's data sent to a client has 9 (`Path::toText(9)`); path-edit checks
  that a saved file's positions are the same after a load and a save
  (failed with 9). PRUDNIK's run data still reads back exactly on a client
  (simulation-wire, server-simulation 40/40).

- **Timetables saved as before** (the user): an unnamed static train's
  `$static` was saved as `S302 $static` (its name added). Now files keep
  `$static` as read, and the name (internal: no file can refer to an
  unnamed train) comes from the column the train has in TSRE's own layout,
  `S` + first train column + its place, the same through saves and in a
  client's copy. Open Rails names it the same in a file TSRE wrote; in a
  file laid out otherwise, by that file's column until TSRE saves it
  (PRUDNIK's 42 show other numbers than before; the trains suite's static
  is S5, Open Rails' S4 in its file without a `#comment` column).
  timetable-read checks the name stays through a save (failed with the
  old rule: S4, then S3); timetable suites, simulation-wire and
  server-simulation on PRUDNIK pass.
- With both, no saved file of a normal route changes on the branch. A TDB
  whose item table has a hole (only from the server's ID blocks or a
  broken file) gets an `EmptyItem` in it instead of nothing (Open Rails
  reads items by their order).

## Task 06 (players), before its merge (2026-11-20)

The user asked for an independent review of task 06 before
`feature/server` goes into main again ("do 1-3 with independent review
included"). One reviewer, new to the code, read `174a3d29..5d9f2938`. It
found nothing of high severity: the server's checks of who may send
which record, the crews' bookkeeping and the driven values' accounting
held. Each finding was checked against the code; each fix has a check
that fails with the fix switched off, except where said.

Fixed:
- **A crew member gone with a key held left the lever moving for the
  rest.** Keys that act while held (a lever, a push button) send their
  release only from the client's own Leave or Drive; a dropped
  connection sends none, and the train was driven on. The server now
  keeps each player's held commands (by `DrivingKeys`' release values)
  and lets them go when it leaves while others drive on.
  (server-simulation: "a crew member gone with its key held")
- **One crash ended the contact checks of every driven train**: after
  it, every other driven train drove through the trains ahead. The
  checks go on after a crash; the first crash is the run's, a later one
  told by its event. A local run's driven train also stays behind the
  train it ran into now. (driving: "driven on after the crash")
- **The Timetable window's Join sat on a checked button**: a player
  driving one train, choosing another's shared cab, clicked Join and
  left the train they drove instead. The button is checked only while the
  player drives and no such train is chosen; one function sets its
  text, state and check, also as the crews change. (server-simulation:
  "the Timetable window: Join on a shared cab")
- **A cab joined, or a driven train heard, while the run is paused got
  no values until a new frame.** The frame is sent again with them.
  (server-simulation: "a cab joined while the run is paused", "a
  driven train heard while the run is paused")
- **A Drive between a console reset (or a run back to a time) and its
  announcement drove the new run's train for nobody.** Drive, Leave,
  Share and Command now need the run announced to be the session's.
  Not checked by a suite: the window is one tick (33 ms) between two
  processes.
- **A second Drive before the frames showed the first left nothing**:
  both trains were driven. The controller leaves the train asked for
  before as well, and forgets it with the run. (simulation-ui: "two
  Drives in a row")
- **Share was not a driving record for the permission check; Drive and
  Command came from clients not showing the run; Ready(false) did not
  leave the cab.** Fixed. (server-simulation: "a Drive from a client
  not showing the run", "a client letting the run go")
- **The wire's layout changed without a version.** `NetworkMessage::
  Protocol` is 2 (an older TSRE is refused at its hello, with the
  reason) and the run's records' version 2. The server suite follows the
  constant.
- **The Shared cab box's check tested nothing** (a window never shown is
  never visible): it checks the box is there and off.

Not changed:
- **A driven train a client stops hearing keeps its last values** on
  that client: its lamps, pantographs and doors as last heard. Its
  sounds stop. The last values are closer to the truth than none; the
  whole fix is a driven train's look in the shared frame, later.
- **Whether one crash ends the run for every player** is the user's
  call: the first crash still marks the run finished for all, as in a
  local run.
