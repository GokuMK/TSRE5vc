# Review of feature/server before its merge (2026-11-19/20)

The user asked for an independent review before `feature/server` is
merged. Three reviewers, each new to the code, read what a merge would
bring into main (`main...8338ef73`, about 12,000 lines):

- tasks 01 and 02: the server, the protocol;
- task 05: the simulation on the server;
- task 03 and editor task 10: the route's files, the route switch.

Each finding was checked against the code before it was fixed. Each fix
has a suite check that fails with the fix switched off, except where said.

The user's decisions during the review:
- **The merge comes after task 06 (players)**, the feature's minimum;
  task 07 is not needed for it.
- **The users file is `users.json` in the profile's folder** (a profile
  names one server session: its game root, route, settings and users,
  moved as one folder, never shipped with content). Plain passwords: the
  admin hands them out. `--users <file>` still overrides. The route
  folder's `users.txt` is no longer read; nobody used the broken mode.

## After the review (2026-11-20)

- **Paths saved with 6 digits again** (the user): task 05 had made the
  path writer use 9 significant digits for the run's data, and with it
  every saved path. Six is the most a decimal keeps through a float and
  back, so loading and saving again never changes the file; with nine,
  values recomputed between saves changed their last digits. Now only a
  run's data sent to a client has 9 (`Path::toText(9)`); path-edit checks
  that a saved file's positions are the same after a load and a save
  (failed with 9). PRUDNIK's run data still reads back exactly on a client
  (simulation-wire, server-simulation 40/40).

- **Timetables saved as before** (the user): an unnamed static train's
  `$static` was saved as `S302 $static` (its name added). Now only a run's
  data sent to a client has the name (`OrTimetable::toText(true)`); a saved
  timetable keeps `$static` as read. timetable suites, simulation-wire and
  server-simulation on PRUDNIK pass.
- With both, no saved file of a normal route changes on the branch. A TDB
  whose item table has a hole (only from the server's ID blocks or a
  broken file) gets an `EmptyItem` in it instead of nothing (Open Rails
  reads items by their order).
