# Undo

## State model

Editor actions group their changes between `Undo::StateBegin()` and
`Undo::StateEnd()`. An undo state can contain cloned world-object data,
placed or removed world objects, terrain and texture data, and snapshots of
the rail and road databases. Undo is currently LIFO, keeps at most 50 states,
and has no redo stack.

Interactive previews should remain inside one open state. The state is ended
only when the user accepts the action. Cancelling a preview restores or removes
the draft object and calls `Undo::StateCancel()` so pointer movement does not
create undo entries.

## Dynamic Track and Flex transactions

Accepting a Dynamic Track can change three related kinds of data:

1. the Dynamic Track world object;
2. rail or road TDB topology;
3. route-local `TSection` and `TrackShape` definitions generated by
   `TDB::fillDynTrack()`.

These changes must be recorded in the same undo state. Continuous Flex records
one accepted main segment and all its companion tracks as one state. The next
unfinished preview belongs to a new state.

TDB snapshots deliberately share the route's `TSectionDAT`; the complete
global and route section database is not deep-copied. Instead, the undo state
records `routeMaxIdx` and `routeShapes` before and after the transaction.
Because `fillDynTrack()` appends new definitions, undo can remove precisely the
definitions appended by that state and restore the old counters.

Rollback removes generated definitions only when the current counters still
equal the recorded post-transaction counters. If another, untracked operation
has appended definitions in the meantime, undo leaves the generated entries as
an unused cache rather than risk removing definitions used by newer data. The
world objects and TDB snapshot are still restored.

Equivalent Dynamic Tracks reuse an existing generated TrackShape. In that
case the before and after counters are equal and there is no section data to
remove.

## Property edits

Dynamic Track section enable switches and section length, angle, and radius
values clone the object before modification. Spin boxes have keyboard tracking
disabled so typing a value creates one undo item when the edit is committed,
rather than one item for every typed digit. Template and elevation edits use
the same world-object snapshot mechanism.

Editing a Dynamic Track which is already present in TDB remains disallowed by
Live Flex. Database geometry must be removed or rebuilt through the existing
TDB workflow so the object and database cannot silently diverge.
